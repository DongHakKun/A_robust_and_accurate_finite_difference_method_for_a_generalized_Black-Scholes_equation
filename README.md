# Generalized Black–Scholes Equation

An **unofficial C++17 implementation** reproducing the numerical experiments in [Cen and Le (2011)](https://doi.org/10.1016/j.cam.2011.01.018), *A robust and accurate finite difference method for a generalized Black–Scholes equation*.

The project reproduces Tests 1 and 2 from Section 5, including Figures 1–2 and Tables 1–2, through Jupyter notebooks using the xeus-cpp kernel. This is an independent reproduction, not the authors' official code.

## Overview

The solver combines payoff smoothing, the paper's piecewise uniform spatial mesh, central differences in space, and implicit Euler stepping backward from maturity. Each time step solves a tridiagonal system with the Thomas algorithm.

All numerical calculations, interpolation, and error analysis run in C++. Plots are generated by calling gnuplot from C++.

## Getting Started

### Requirements

- Linux or WSL
- Conda

The supplied [environment.yml](environment.yml) installs xeus-cpp, C++ compiler dependencies, JupyterLab, and gnuplot in a separate environment.

### Installation

```bash
git clone https://github.com/DongHakKun/A_robust_and_accurate_finite_difference_method_for_a_generalized_Black-Scholes_equation.git generalized-black-scholes
cd generalized-black-scholes
conda env create -f environment.yml
conda activate black-scholes-cpp
```

### Usage

From the repository root, start JupyterLab:

```bash
jupyter lab ipynb/
```

Start with [Numerical Method and Experiment Setup](ipynb/00_Numerical_method_and_experiment_setup.ipynb), then continue to Test 1 and Test 2. Select the xeus-cpp **C++17** kernel, then restart the kernel and run all cells. The saved notebooks use the custom kernel name `black-scholes-cpp`; select the installed C++17 kernel if that name is unavailable. The kernel's working directory must be `ipynb/` so relative include and output paths resolve correctly.

For VS Code, open the project in WSL and select the C++17 kernel. Restart the kernel and rerun all cells after changing C++ definitions.

## Reproducing the Paper

Both tests use `T = 1`, `r = 0.06`, `K = 25`, `Smax = 100`, and `epsilon = 1e-4`.

| Test | Volatility | `alpha` | `betaStar` |
|---|---|---:|---:|
| 1 | `sigma(x,t) = 0.2 * (1 + t * exp(-x))` | 0.04 | 0.06 |
| 2 | `sigma(x,t) = 0.4 * (2 + sin(x))` | 0.16 | 0.06 |

Here, `alpha` bounds `sigma^2` from below and `betaStar` bounds the interest rate from above. These choices use the tight coefficient bounds and reproduce the published tables.

- **Figures 1–2:** `N = M = 64`.
- **Tables 1–2:** `M = 1024`, with `N = 128, 256, 512, 1024`.
- **Reference solution:** `N = 2048`, `M = 1024`.

The reference solution is interpolated linearly in space at matching time levels. Errors are measured over **all spatial nodes and time levels**, rather than only at `t = 0`. Spatial meshes are not assumed to be nested.

|---:|---:|---:|---:|---:|
| 128 | 6.80267592e-2 | 1.122 | 5.71239536e-2 | 1.551 |
| 256 | 3.12581899e-2 | 1.312 | 1.94981844e-2 | 1.919 |
| 512 | 1.25878300e-2 | 1.880 | 5.15498502e-3 | 2.284 |
| 1024 | 3.41885173e-3 | — | 1.05863181e-3 | — |

All eight error values and six convergence rates match the printed precision of Tables 1–2. Each rate compares the current row with the next, using `log2(error(N) / error(2N))`.

The reference solution is numerical, so these values do not measure total error against an exact solution. Since the time grid is fixed, the tables also do not establish a temporal convergence rate. The notebooks discuss local truncation error at mesh transition points and the limits of interpreting observed rates.

## Validation

Numerical checks cover the Thomas solver, mesh landmarks, payoff smoothing, boundary conditions, time direction, residuals, interior M-matrix properties, interpolation between nonnested meshes, and maximum errors over all time levels. They also verify the published tables and error reduction against the constant-volatility Black–Scholes exact solution.

All three notebooks have been executed successfully with the C++17 kernel using only the published source files, regenerating all 30 result files without local reference materials or development archives.
